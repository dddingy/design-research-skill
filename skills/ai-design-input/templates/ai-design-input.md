# AI Design Input

> 供 AI 设计稿和交互 demo 使用。只记录设计生成必须遵守的硬逻辑；背景、目标与评审说明以 Requirement Brief / Design Definition 为准。

## 1. Scope & Roles

### In Scope
- [本次必须设计或改造的页面、容器、能力。]

### Out of Scope
- [材料明确排除的范围。]

### Roles & Permissions
- [只写会改变可见内容、操作、流程或状态的角色差异。]

## 2. Page / Container Map

| 页面 / 容器 | 类型 | 本次处理方式 | 承载内容 / 用户任务 |
|---|---|---|---|
|  | 新设计 / 现有页改造 / 现有页复用 / 未来扩展 |  |  |

## 3. Logic Model

### Core Objects
- [核心对象与关键属性。]

### Object Relationships
- [对象关系、数量关系、归属 / 推荐 / 创建 / 分组关系。]

### Item & Action Grain
- [列表项、卡片、提交、隐藏、完成、draft 等最小生效粒度。]

## 4. User Flow

### Main Flow
1. [入口或触发。]
2. [关键用户动作与系统反馈。]
3. [结果与承接。]

### Branches / Return / Exceptions
- [仅写材料明确且会影响页面或状态的分支、回流和异常。]

## 5. States, Actions & Rules

- [状态或条件]：用户动作、系统反馈、生效范围、后续状态。
- [权限或风险规则]：只写会改变界面或流程的规则。

## 6. Content Requirements

- [页面必须承载的信息、字段、操作、提示和反馈。]

## 7. Existing Surfaces & Reuse

- [现有页面、组件、流程及复用边界。]
- [现有页改造时，补充截图中可确认的布局与承载上下文。]

## 8. Confirmed Design Generation Instructions

- [只写用户已确认采纳的设计方向、竞品参考或视觉约束；没有时写「暂无已确认的设计生成指令」。]

## Blocking Open Questions

- [只保留会改变页面范围、流程、对象关系、权限、状态或操作粒度的问题；没有时写「无」。]
